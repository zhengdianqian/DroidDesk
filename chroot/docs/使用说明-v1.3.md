# chroot 方案使用说明 v1.3（2026-11-05 实测）

设备：Redmi Pad Pro / `dizi`（`e59bd947`），KSU 3.3.0（内核 `u:r:ksu:s0`，越狱模式），
rootfs：Ubuntu 26.04 resolute（`/data/chroot/ubuntu`），桌面：KDE Plasma 6 X11 + Termux:X11。

---

## 1. 图形 / 容器分离语义

| 动作 | 脚本 | 挂载 | chroot 进程 | X 会话 / 桌面 |
|---|---|---|---|---|
| 启动容器（仅命令） | `ubuntu-start.sh --mount-only` | 建 6 条 | 保留（dbus 等） | 不启动 |
| 启动容器（图形） | `ubuntu-start.sh --gui` | 建 6~7 条 | chroot 内保留 | 启动 X + KDE |
| 打开图形（容器保持运行） | `ubuntu-start.sh --gui`（容器在跑时不带 `--force`） | 不变 | 不变 | 只拉起 X + KDE |
| **关闭图形（容器保持运行）** | `ubuntu-stop.sh --gui-only` | **不卸载**（只卸 `/tmp/.X11-unix`） | **不杀** | 杀 KWin/plasmashell/startplasma + `am force-stop com.termux.x11` |
| 停止容器 | `ubuntu-stop.sh --force` | 全卸载（`umount -l` 兜底） | 全杀 | 先关图形 |

实测（`ubuntu-stop.sh --gui-only` 后）：
`container=1, gui=0, desktop=0, x11=0, mounts=6, chroot 进程由 31 降到 25`，桌面进程与 X socket 均消失。

## 2. APK 用法（`com.trae.ubuntu.container` v1.3）

- 状态区：ROOT 通道 / 容器 / 图形 / 挂载数 / chroot 进程数 / X11 / 分辨率。
- 按钮：启动容器（图形）、启动容器（仅命令）、打开图形、关闭图形、停止容器、刷新状态。
- 每个动作完成后结果区给出「成功/失败 + 原因 + 耗时 + 状态摘要 + 脚本尾部日志」。

### 特权通道（重要）

KSU 3.3.0 越狱模式对**未授权应用隐藏 `/system/bin/su`**，且本应用不在 `/data/adb/ksu/.allowlist`，
`exec("/system/bin/su")` 直接返回 `ENOENT`，因此 APK 无法用 `su -c` 提权。APK 采用两级通道：

1. **root 代理**（默认）：`ubuntu-agent.sh` 以 root 监听 `127.0.0.1:47123`，APK 用一次性 token
   （`/data/data/com.trae.ubuntu.container/files/agent.token`，600，属主 APP uid）鉴权，
   代理仅接受白名单动作：`status / start-cmd / start-gui / gui-off / stop / ping`。
2. **su 兜底**：若应用被 KSU 授权，则直接用 `su -c`（`/system/bin/su` 等候选路径逐个尝试）。

两者都不可用时，界面直接提示「先恢复 ROOT」，不会静默失败。

启动代理（root shell 里执行一次）：

```sh
su -c 'sh /data/local/tmp/ubuntu-agent.sh start'
su -c 'sh /data/local/tmp/ubuntu-agent.sh status'
```

> 设备重启后代理不会自动启动（未写入 `/data/adb`，遵守"不动 KSU"约束）。
> 如需开机自启，由用户自行决定是否把 `ubuntu-agent.sh start` 放进 `/data/adb/service.d/`。

## 3. 底部遮挡（Termux:X11 盖住 Dock / 手势条）

**根因**：Termux:X11 偏好里 `showAdditionalKbd=true`，底部额外按键条占掉一条屏幕，
X 屏幕被压到 `2560x1450`，KDE 面板正好落在按键条下面。

**处理**：`ubuntu-start.sh --gui` 启动前自动修正 Termux:X11 偏好
（`/data/data/com.termux.x11/shared_prefs/com.termux.x11_preferences.xml`）：

```
fullscreen          = false
showAdditionalKbd   = false
additionalKbdVisible= false
adjustHeightForEK   = false
displayResolutionMode = native
```

修正后 X 屏幕为 `2560x1508`，KDE 面板完整可见，Android 手势白条在其下方独立区域，不重叠。

**另外发现的坑**：`startplasma-x11` 起来后会被 `kscreenlocker_greet` 全屏锁屏盖住（看起来像"桌面没了"）。
v1.3 在 `start-desktop-x11.sh` 里写入 `~/.config/kscreenlockerrc`：

```ini
[Daemon]
Autolock=false
LockOnStartup=false
```

真机截图：`docs/screenshots/shot-b.png`（修复前，面板被压）、
`shot-b-bottom.png`（修复后底部）、`desktop-dock-gesture.png`（桌面 + Dock + 手势条）。

## 4. 三方软件兼容性

### 4.1 根因

- `/data` 以 **nosuid** 挂载 → Chromium/Electron 的 setuid 沙箱不可用；
- 内核**无 user namespace**（`unshare -U` 返回 EINVAL）→ 新式 userns 沙箱也不可用；
- 结论：Chromium / Electron 系必须显式 `--no-sandbox` 才能启动。

### 4.2 已做的修复

| 项 | 状态 | 说明 |
|---|---|---|
| `/dev/shm` | ✅ 已修 | `mount -t tmpfs -o size=2G,mode=1777 tmpfs $ROOT/dev/shm` |
| `/dev/pts` | ✅ 已修 | `mount -t devpts devpts ... -o gid=5,mode=620,ptmxmode=666`（`--bind /dev` 不带子挂载） |
| system dbus | ✅ 已修 | `chroot ... dbus-daemon --system --fork --nopidfile`，stdin 需 `/dev/null` |
| `XDG_RUNTIME_DIR` | ✅ 已设 | `/run/user/1000`，700，属主 Gold |
| SELinux | ✅ 无拒绝 | `dmesg | grep avc` 无相关记录 |
| Electron/Chromium 沙箱 | ✅ 已绕过 | `fix-thirdparty.sh` 给 11 个 `.desktop` 追加 `--no-sandbox`，并写 `/etc/chromium-browser/default` |
| AppImage | ❌ 受限 | 有 `/dev/fuse` 但无 `fusermount`，且内核 FUSE 未验证；只能 `--appimage-extract` 后直接跑 |
| flatpak | ⚠️ 未验证 | 需要 systemd/用户会话，chroot 内不具备 |

实测成功：Chromium `--no-sandbox` 出窗口（`docs/screenshots/shot-chrome.png`）。

### 4.3 能跑 / 跑不了

- **能跑**：Chromium、Electron 系（加 `--no-sandbox`）、GTK/Qt 原生程序、CLI 工具。
- **跑不了**：依赖 `/dev/fuse` 的 AppImage（未装 fusermount）、flatpak、需要 systemd 的服务。

## APK 构建

```powershell
# 需要：JDK 11+、Android SDK build-tools（aapt2/d8/zipalign/apksigner）
# 注意：构建目录必须是纯 ASCII 路径（aapt2 不认中文路径）
powershell -NoProfile -ExecutionPolicy Bypass -File .\chroot\app\build-apk.ps1
```

产物：`chroot/dist/Ubuntu-Container-v1.3.apk`（33 KB，arm64 无关的纯 Java，minSdk 26 / targetSdk 34）。
签名 keystore 不随仓库分发（`build-apk.ps1` 里改为你自己的 jks 路径即可）。

## 实测记录（2026-11-05）

### 按钮逐项结果

| 按钮 | 结果 | 真实状态核对 | 耗时 |
|---|---|---|---|
| 关闭图形 | ✅ 成功 | `gui=0 desktop=0 x11=0 container=1 mounts=6 procs 31→25`，X socket 已删 | 37.3 s |
| 停止容器 | ✅ 成功 | `mounts=0 procs=0 container=0` | 58.5 ~ 60.7 s |
| 启动容器（仅命令） | ✅ 成功 | `container=1 mounts=6 gui=0 x11=0` | ~30 s（旧版曾卡住，已修） |
| 启动容器（图形）/ 打开图形 | ✅ 成功 | `gui=1 desktop=1 x11=1 res=2560x1508` | ~45 s |

### 启停耗时拆解（stopwatch，2 轮）

```
STOP_FORCE  = 1520 ms（无挂载时；有挂载时 umount 逐条重试，最坏 ~30s）
START_MOUNTS=  298 ms
X_SOCKET    =  379 ms
KWIN        = 1001 ms
```

即**容器本身起停是 1~2 秒级**，APK 上的 40~60s 主要来自旧的 UI 等待逻辑
（`wait_gui` 每次迭代调 `ubuntu-status.sh`，该脚本遍历 `/proc` 且要在 chroot 里跑 `xdpyinfo`，约 12 s/次）。
v1.3 已改为：**200 ms 轮询 + 20 s 上限 + `ps` 轻量检查**，超时返回"图形仍在启动中（后台继续）"，不再卡按钮。
